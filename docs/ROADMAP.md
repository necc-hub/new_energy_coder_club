## 当前阶段：可复现与贡献闭环

| 目标 | 验收标准 | 当前证据 |
|---|---|---|
| 核心入口可信 | 核心导航 CI 持续通过，路径在大小写敏感系统可用 | 已上线并验证 |
| 新人能完成首个贡献 | 至少 1 个 `good first issue` 被认领、评审并合并 | 待首位外部贡献者完成 |
| 活跃项目可复核 | 每个 active 项目有负责人、验证日期、复现命令和下一步 | 待项目负责人补齐 |
| 当前赛季有工程基线 | 机械/电控/视觉/运营均链接到具体版本资产与验证记录 | CURC2027 各组待补 |
| 历史资料逐步修复 | 全仓死链数持续下降，新增 PR 不引入死链 | 已有 Artifact 与任务 #30–#33 |

## 下一阶段：资产复用与赛季沉淀

1. 从学习日志中提炼可复用的选型、调试和故障案例，而非只累积个人记录。
2. 每个完成赛季形成资产包：规则版本、图纸/BOM、代码/模型版本、测试记录和复盘。
3. 为核心教程建立文档站导航；发布前保留仓库内链接检查，避免站点与仓库内容漂移。
4. 形成固定的周/赛季复盘节奏，并在[每周精选模板](community/weekly.md)记录真实 PR 和里程碑。

## 明确不在近期做

- 不为了“像软件项目”引入 Monorepo 构建系统或无实际产物的测试体系。
- 不在未通知协作者时重写 Git 历史或执行全仓 LFS 迁移。
- 不在缺乏真实负责人和验证记录时，把历史项目标成“活跃”。
- 不用文档数量、模板数量或 CI 数量替代实际可复现的工程资产。
