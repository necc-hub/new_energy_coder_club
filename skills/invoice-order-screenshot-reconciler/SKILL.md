# 发票订单截图匹配与审核归档

## 核心边界

- 图像理解由 Agent 完成，脚本不猜测商品归属。金额相同不等于订单相同，必须交叉核对品名、商户、订单号和付款时间。
- 不为了一一对应强行匹配。合并付款、品名冲突、商品未显示必须保留为异常。
- 脚本默认只预检；只有用户要求实际整理时才加 `--apply`。只重命名，不删除发票、截图或凭证。
- “待审核删除”只是文件名标记，最终删除由用户人工完成。异常截图关联的原图不得标待删。
- 不把真实发票、支付流水、订单号或个人信息写进技能示例和测试。

## 输入

需要 Python 3、已安装的 `openpyxl`、一个分类包目录、19列票款核对总表和人工核对后的映射JSON。先用 `python -c "import openpyxl"` 确认依赖可用。总表默认列位：`A序号 / B分类 / J发票金额 / O核对状态 / P复核事项 / Q发票文件 / R付款及订单凭证 / S备注`，可用 `columns` 覆盖。

目录约定：

```text
分类包/
├── 01_正常报销_票款一致_付款齐全/
│   ├── 发票01_10.00元_示例商品.pdf
│   ├── 发票01_10.00元_示例商品_付款记录_01.png
│   └── 微信图片_待整理.jpg
├── 10月票款核对总表.xlsx
└── 10月票款核对总体看板.html   # 可选
```

## 标准流程

### 1. 盘点并逐张读图

- 列出未命名截图、发票PDF和现有付款截图；记录文件数量，后续不得通过删除来凑数。
- 用媒体读取工具逐张查看新截图，记录商品、实付金额、商户、订单号、付款时间。
- 读取对应发票的文字层或图像，核对品名与金额。需要批量识别时复用 `invoice-detect-dashboard`，不要用无坐标重组的裸文本提取代替。

### 2. 人工判定并填写映射

复制 `config.example.json`，修改路径、总表名称、金额笔数及 `screenshots`。每条新截图只能选择以下状态：

| `status` | 含义 | 原付款截图处理 |
|---|---|---|
| `matched` | 品名和金额等证据确认一一对应 | 标“待审核删除” |
| `review_product` | 金额/时间一致，但品名未显示或仍待确认 | 可标待审核，但必须保留复核提示 |
| `unmatched_combined` | 多商品合并付款，不能拆成单张发票 | 原图保留，不标待删 |
| `unmatched_conflict` | 金额可能相同，但品名等关键证据冲突 | 原图保留，不标待删 |

`matched` 和 `review_product` 必填 `invoice_seq`、`amount`、`product`、`match_basis`、`advice`。`unmatched_combined` 使用 `possible_invoices`，`unmatched_conflict` 使用 `invoice_seq`；异常还要填写 `label`、`match_basis` 和 `advice`。`source_tag` 用于短文件名，例如“微信316”。

### 3. 先预检，再执行

```bash
python scripts/reconcile_order_screenshots.py --config config.json
python scripts/reconcile_order_screenshots.py --config config.json --apply
```

预检和执行都会检查：

- 所有源图、发票和原付款截图存在，目标文件名无冲突。
- `matched` / `review_product` 的映射金额与总表发票金额一致。
- 总表总笔数、总金额、正常报销笔数与金额符合 `expected_totals`，防止误改其他记录。
- 执行前后逐文件SHA-256一致；所有工作簿可重新打开，Excel和HTML本地链接有效。

### 4. 输出与总表同步

执行后在正常报销目录生成：

- `订单截图匹配审核清单_<report_date>.xlsx`：逐笔状态、匹配依据、审核建议、文件链接，以及重命名哈希明细。
- `订单截图匹配审核看板_<report_date>.html`：零依赖响应式看板，可逐笔打开新截图、发票和原图。
- `正常报销清单_<report_date>.xlsx`：按总表正常类别生成，保留总览和明细样式。

同时更新总表付款凭证列：新截图排在首位，原截图名称同步替换；`review_product` 在复核事项中追加提示。配置 `main_dashboard` 时，同步重建逐笔文件对应表，缺少的文件显示“未随分类包”文字，不生成死链。

### 5. 验证与交付

```bash
python scripts/selftest.py
```

实际任务还必须复核：未命名源图数量已归零、四类状态数量正确、原图标记数量正确、总表笔数和金额未变、全部本地链接有效，并实际打开HTML和抽查图片链接。

回复用户时给出：确认匹配数、品名待核数、未匹配数、待审核删除原图数、异常原因、审核Excel/HTML路径、更新后的总表路径。若重新跑了发票识别，另按 `invoice-detect-dashboard` 要求输出发票识别总看板及识别指标。

## 易错点

1. 同金额、同商户、同时间仍可能品名冲突，必须标 `unmatched_conflict`。
2. 一张合并付款图不能同时充作多张发票的一一对应凭证。
3. Excel单元格只能提供一个原生超链接；多张原图在看板和“重命名哈希” sheet 中逐张提供链接。
4. Windows长路径下使用短文件名和 `source_tag`，不要把完整商品名全部塞进文件名。
5. 不要为了让看板“全部正常”而隐藏异常；缺文件改成文字提示，不创建空发票或空凭证。
